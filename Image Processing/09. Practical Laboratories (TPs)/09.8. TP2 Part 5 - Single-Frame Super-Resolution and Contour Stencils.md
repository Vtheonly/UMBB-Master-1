## 2. Dataset — Triplet Discovery
The assignment downloads the `Images_TP2_EXO6_SR` archive: 69 JPGs split evenly over `HR_GT_512x512`, `LR_256x256` and `LR_128x128` (23 triplets). `discover_sr_triplets` (`TAI/utils/super_res.py`) locates them with three fallback cases: **(A)** the official set consolidated under `TAI/images/` (files `tp2_exo6_sr_hr_gt_512x512_*`, `tp2_exo6_sr_lr_256x256_*`, `tp2_exo6_sr_lr_128x128_*`), **(B)** the extracted archive folder, or **(C)** a deterministic 5-image demonstration set generated inside `TAI/outputs/` (never committed) from standard TAI images, so the notebook always runs end-to-end. ## 3. OpenCV Interpolation Benchmark (2x, 4x direct, double 2x)
Task 2 of the exercise benchmarks `INTER_NEAREST`, `INTER_LINEAR` and `INTER_CUBIC` at 2x on the 256×256 inputs and at 4x on the 128×128 inputs — both directly and as two chained 2x passes — scoring each reconstruction against `HR_GT` with PSNR **and** SSIM:

```python
from TAI.utils.metrics import calculate_psnr, calculate_ssim

interp_methods = [
    ("Nearest neighbour", cv2.INTER_NEAREST),
    ("Bilinear", cv2.INTER_LINEAR),
    ("Bicubic", cv2.INTER_CUBIC),
]

summary = {}
for m_name, m_flag in interp_methods:
    for mode in ("2x (256->512)", "4x direct (128->512)", "Double 2x (128->256->512)"):
        summary[(m_name, mode)] = {"psnr": [], "ssim": []}

for p_hr, p_l2, p_l4 in triplets:
    hr = cv2.imread(str(p_hr), cv2.IMREAD_COLOR)
    l2 = cv2.imread(str(p_l2), cv2.IMREAD_COLOR)
    l4 = cv2.imread(str(p_l4), cv2.IMREAD_COLOR)
    h_hr, w_hr = hr.shape[:2]

    for m_name, m_flag in interp_methods:
        pred_2x = cv2.resize(l2, (w_hr, h_hr), interpolation=m_flag)
        pred_4x = cv2.resize(l4, (w_hr, h_hr), interpolation=m_flag)
        mid_2x = cv2.resize(l4, (l2.shape[1], l2.shape[0]), interpolation=m_flag)
        pred_2x2x = cv2.resize(mid_2x, (w_hr, h_hr), interpolation=m_flag)
        for mode, pred in (("2x (256->512)", pred_2x),
                           ("4x direct (128->512)", pred_4x),
                           ("Double 2x (128->256->512)", pred_2x2x)):
            summary[(m_name, mode)]["psnr"].append(calculate_psnr(hr, pred))
            summary[(m_name, mode)]["ssim"].append(calculate_ssim(hr, pred))

for (m_name, mode), v in summary.items():
    print(f"{m_name:18s} {mode:24s} PSNR {np.mean(v['psnr']):6.2f} dB"
          f"  SSIM {np.mean(v['ssim']):.4f}")
```

Measured on the deterministic demonstration set (5 triplets; the official 23-triplet set gives the same ordering):

| Method | Factor | mean PSNR | mean SSIM |
| :--- | :--- | :--- | :--- |
| Nearest | 2x (256→512) | 28.60 dB | 0.8660 |
| Bilinear | 2x (256→512) | 29.63 dB | 0.8589 |
| Bicubic | 2x (256→512) | **31.96 dB** | **0.8849** |
| Nearest | 4x direct (128→512) | 23.82 dB | 0.6956 |
| Bilinear | 4x direct (128→512) | 24.69 dB | 0.7181 |
| Bicubic | 4x direct (128→512) | 25.38 dB | 0.7376 |
| Bilinear | Double 2x (128→256→512) | 24.37 dB | 0.7031 |
| Bicubic | Double 2x (128→256→512) | 25.40 dB | 0.7373 |

**Reading the table:** bicubic leads the linear family at both factors (its 16-pixel neighbourhood reconstructs smooth gradients better), nearest stair-cases badly, and the double-2x path lands within ±0.03 dB of the direct 4x for bicubic — cascading *fixed* kernels accumulates only rounding and grid-phase shifts.

## 4. From-Scratch Bilinear 2x (Task 3)
`super_resolution_bilineaire_2x` (`TAI/utils/super_res.py`) implements bilinear 2x upsampling from scratch with **OpenCV's pixel-centre alignment** — the source coordinate of output row `i` is `(i + 0.5)/2 - 0.5` — so the scratch result matches `cv2.resize(..., INTER_LINEAR)` up to rounding:

```python
from TAI.utils.super_res import super_resolution_bilineaire_2x

psnr_cv, psnr_perso, max_diffs = [], [], []
for p_hr, p_l2, _ in triplets:
    hr = cv2.imread(str(p_hr), cv2.IMREAD_COLOR)
    l2 = cv2.imread(str(p_l2), cv2.IMREAD_COLOR)
    b_cv = cv2.resize(l2, (hr.shape[1], hr.shape[0]), interpolation=cv2.INTER_LINEAR)
    b_perso = super_resolution_bilineaire_2x(l2, opencv_align=True)
    psnr_cv.append(calculate_psnr(hr, b_cv))
    psnr_perso.append(calculate_psnr(hr, b_perso))
    max_diffs.append(int(np.max(np.abs(b_cv.astype(np.int16) - b_perso.astype(np.int16)))))

print(f"Bilinear 2x OpenCV mean PSNR : {np.mean(psnr_cv):.4f} dB")
print(f"Bilinear 2x custom  mean PSNR: {np.mean(psnr_perso):.4f} dB")
print(f"Max pixel difference OpenCV vs. custom: {max(max_diffs)} level(s) (rounding only)")
```

Measured: 29.633 dB vs 29.630 dB, max difference **1 level** — the parity check the assignment asks for ("comparer les résultats obtenus à ceux d'OpenCV").

## 5. Contour-Stencil Interpolation (Task 4) and the 4x Cascade
`super_resolution_contour_stencils_2x(image, rho=0.5)` is the full Getreuer (2009) method — the derivation, the 12-stencil table and the four rule groups are tabulated in [[24. Super-Resolution and Edge-Adaptive Interpolation - Pascal Getreuer Contour Stencils]] §3–§5. In brief: directional differences feed 12 weighted, length-normalized TV maps; each map is smoothed by a Gaussian `G_rho` (paper Remark 1); colour TV uses the ℓ1 norm in YCrCb (Remark 3); `argmin` selects the winning stencil per cell; the rule groups fill the mid-points `N/S/W/E` and centre `X`; shared mid-points are averaged between adjacent cells on the **`(2h, 2w)`** output grid. Factor 4 uses **pyramid magnification** — the 2x operator applied twice, re-estimating orientations on the intermediate image:

```python
from TAI.utils.super_res import super_resolution_contour_stencils_2x

cs_2x_psnr, cs_2x_ssim, bic_2x_psnr = [], [], []
cs_4x_psnr, cs_4x_ssim, bic_4x_psnr = [], [], []
for p_hr, p_l2, p_l4 in triplets:
    hr = cv2.imread(str(p_hr), cv2.IMREAD_COLOR)
    l2 = cv2.imread(str(p_l2), cv2.IMREAD_COLOR)
    l4 = cv2.imread(str(p_l4), cv2.IMREAD_COLOR)

    bic_2 = cv2.resize(l2, (hr.shape[1], hr.shape[0]), interpolation=cv2.INTER_CUBIC)
    cs_2 = super_resolution_contour_stencils_2x(l2, rho=0.5)
    bic_4 = cv2.resize(l4, (hr.shape[1], hr.shape[0]), interpolation=cv2.INTER_CUBIC)
    cs_4 = super_resolution_contour_stencils_2x(
        super_resolution_contour_stencils_2x(l4, rho=0.5), rho=0.5
    )

    bic_2x_psnr.append(calculate_psnr(hr, bic_2)); cs_2x_psnr.append(calculate_psnr(hr, cs_2))
    cs_2x_ssim.append(calculate_ssim(hr, cs_2))
    bic_4x_psnr.append(calculate_psnr(hr, bic_4)); cs_4x_psnr.append(calculate_psnr(hr, cs_4))
    cs_4x_ssim.append(calculate_ssim(hr, cs_4))

print(f"Bicubic 2x          : PSNR {np.mean(bic_2x_psnr):6.2f} dB")
print(f"Contour stencils 2x : PSNR {np.mean(cs_2x_psnr):6.2f} dB  SSIM {np.mean(cs_2x_ssim):.4f}")
print(f"Bicubic 4x          : PSNR {np.mean(bic_4x_psnr):6.2f} dB")
print(f"Contour stencils 4x : PSNR {np.mean(cs_4x_psnr):6.2f} dB  SSIM {np.mean(cs_4x_ssim):.4f}")
```

Measured on the demonstration set: bicubic 2x 31.96 dB vs stencils 2x **27.52 dB / SSIM 0.8309**; bicubic 4x 25.38 dB vs stencils 4x (2x2x cascade) **22.55 dB / SSIM 0.6569**.

**Why raw PSNR favours bicubic here — and why the assignment still wants the comparison.** The demonstration triplets are generated with `cv2.resize`, i.e. OpenCV's *centred* grid alignment $(i+0.5)/s - 0.5$, while the stencil operator uses the *cellular* placement $v_{i,j} \mapsto (2i, 2j)$ — a half-pixel phase shift that PSNR charges to the stencil image even where it is visually sharper. This is exactly the grid-dependence Getreuer discusses: the metric ranks *alignment-compatible* methods first. The notebook therefore reports PSNR **and** SSIM and inspects zoomed crops (HR vs nearest/bilinear/bicubic/stencils on a central 160×160 patch): nearest stair-cases, bilinear softens, bicubic shows slight overshoot near edges, and the stencil reconstruction keeps **one-pixel transitions with directional coherence** — verified on a synthetic step edge (0 | 200), which the operator reconstructs as `0, 0, 0, 100, 200, 200, 200, 200` where a bilinear resize would produce a multi-level ramp.

## 6. Results Analysis (assignment deliverables)
- **Best interpolation method:** bicubic leads the *linear* family on this benchmark in both PSNR and SSIM; nearest is clearly worst (stair-casing).
- **SR 4x vs double 2x (128→512):** for fixed kernels the two paths differ only by rounding/grid phase (bicubic 25.38 vs 25.40 dB). For the *adaptive* stencil operator the cascade is the recommended scheme (paper §3.3): each pass re-estimates edge orientations before refining further.
- **Where stencils win:** edge sharpness and directional coherence without stair-casing or overshoot (paper Figure 6); raw PSNR/SSIM on centred-grid datasets under-report this advantage.
