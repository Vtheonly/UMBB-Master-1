# 02.3. Dictionaries, Sets, Tuples, and High-Performance Collections

## 1. Overview
This note covers Python's core collection types: immutable tuples, hash-table-backed dictionaries and sets, and the double-ended queue (`deque`).

## 2. Structural Comparison

| Collection | Syntax | Mutability | Ordering | Hash Table Backed | Lookup Complexity | Primary Use Case |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Tuple** | `(1, 2, 3)` | Immutable | Ordered | No | $O(n)$ search, $O(1)$ index | Fixed records, database row tuples, hashable dictionary keys |
| **Dictionary**| `{"k": "v"}` | Mutable | Ordered (3.7+) | Yes | $O(1)$ average | Key-value mapping, metadata storage |
| **Set** | `{1, 2, 3}` | Mutable | Unordered | Yes | $O(1)$ average | Deduplication, membership testing, set mathematics |
| **Deque** | `deque([1, 2])`| Mutable | Ordered | No (Doubly Linked) | $O(1)$ ends, $O(n)$ middle | Stacks (LIFO) and Queues (FIFO) |

## 3. Tuples in Practice (Chapter 3 examples)
Tuples are immutable sequences — fixed records that cannot grow, shrink, or
be re-assigned per element:

```python
# Packing and unpacking
point = (3, 7)                    # packing
x, y = point                      # unpacking
name, age, city = "Sara", 21, "Oran"   # tuple-free unpacking works too

# Single-element tuple needs the trailing comma!
single = (5,)                     # tuple of one element
not_a_tuple = (5)                 # just int 5, parenthesized expression

# Common uses
coordinates = [(35.7, -6.1), (36.7, 3.2)]   # fixed (lat, lon) records
lookup = {(1, 2): "origin-adjacent"}         # tuples are hashable -> dict keys
print(len(point), point[0], point[1])        # indexing works, assignment does not
```

Immutability is what makes tuples hashable (usable as dictionary keys / set
members) — a mutable list would break the hash tables below.

## 4. Hash Table Mechanics: Dictionaries and Sets
Python dictionaries and sets rely on open addressing hash tables.
1. When inserting key $k$, Python computes its hash: $h = \text{hash}(k)$.
2. $h$ is mapped to an index within the hash table bucket array.
3. If an index collision occurs, Python probes other slots until a free one
   is found.

> [!tip] CPython probing — supplementary, beyond core exam scope
> The exact CPython probe sequence is
> $i = (5i + 1 + \text{perturb}) \bmod \text{size}$ with `perturb` mixing
> hash bits. Chapter 3 only requires the model: hash → index, collisions
> resolved by probing, average $O(1)$ operations.

*Requirement*: Any object used as a dictionary key or set member must be **hashable** (implementing an immutable `__hash__()` and `__eq__()`). Mutable objects like lists cannot be used as dictionary keys.

### Dictionary Safe Access and Mutation
```python
person = {"name": "Ali", "age": 30, "city": "Alger"}

# Safe retrieval avoiding KeyError exceptions
email = person.get("email", "Not Registered")

# Mutation and element removal
person["age"] = 31             # In-place update
del person["city"]             # In-place deletion

# Extracting view objects
keys = person.keys()
values = person.values()
items = person.items()
```

### Set Methods and Mathematics (Chapter 3 operations)
```python
set_a = {1, 2, 3}

set_a.add(4)              # Insert a single element
set_a.add(3)              # No effect: duplicates are ignored
set_a.discard(99)         # Remove if present, NO error if absent
set_a.remove(2)           # Remove; raises KeyError if absent
popped = {7, 8, 9}.pop()  # Remove and return an arbitrary element

b = {3, 4, 5}
print(set_a | b)          # {1, 3, 4, 5}  union
print(set_a & b)          # {3}           intersection
print(set_a - b)          # {1, 4}        difference
print(set_a ^ b)          # {1, 4, 5}     symmetric difference
```

The `discard` vs `remove` distinction is a classic exam trap: only `remove`
raises `KeyError` on a missing element.

## 5. Stacks (LIFO) and Queues (FIFO) with `collections.deque`
While a standard Python list can function as a stack (using `append()` and `pop()` in $O(1)$ time), using it as a FIFO queue (using `list.pop(0)`) requires shifting every remaining element left, running in $O(n)$ time.
`collections.deque` uses a doubly linked list of fixed-size memory blocks, providing $O(1)$ time complexity for insertions and deletions at both ends.

```python
from collections import deque

queue = deque()
queue.append("Patient A")      # Enqueue
queue.append("Patient B")
first_served = queue.popleft() # Dequeue in O(1) time
print(f"Served: {first_served}, Remaining: {list(queue)}")
```
