### Step 3: Analysis Notebook (`notebooks/patients_analysis.ipynb`)

#### Cell 1: Ingestion and Structural Inspection
```python
import pandas as pd
import matplotlib.pyplot as plt

# Load patient cohort using a relative path
df = pd.read_csv("../data/patients.csv")

# Print dataset dimensions and memory summary
print(f"Cohort Dimensions: {df.shape[0]} rows, {df.shape[1]} columns")

```

#### Cell 2: Descriptive Statistical Summaries
```python
print("--- Continuous Clinical Features ---")
display(df.describe())

print("\n--- Sex Categorical Frequency Distribution ---")
print(df['Sex'].value_counts())

print("\n--- Clinical Diagnosis Frequency Distribution ---")

```

#### Cell 3: Clinical Visualization
```python
fig, ax = plt.subplots(figsize=(8, 5))

# Plot Age vs. Cholesterol with styled markers
scatter = ax.scatter(
    df['Age'], 
    df['Cholesterol'], 
    c=df['BloodPressure'], 
    cmap='viridis', 
    s=100, 
    alpha=0.85, 
    edgecolors='black', 
    linewidth=1.2
)

cbar = fig.colorbar(scatter, ax=ax)
cbar.set_label('Blood Pressure (mmHg)', fontsize=11)

ax.set_title("Patient Age vs. Serum Cholesterol Levels", fontsize=14, fontweight='bold', pad=12)
ax.set_xlabel("Patient Age (Years)", fontsize=11)
ax.set_ylabel("Serum Cholesterol (mg/dL)", fontsize=11)
ax.grid(True, linestyle='--', alpha=0.5)

plt.tight_layout()
plt.show()
```

## 7. TP2 Steps 4 & 5 — GitHub Repository and Environment Sharing
Steps 4–5 of the tutorial turn the local analysis folder into a shared,
reproducible GitHub project (implemented in the lab as
`APDS/01_Hospital_Data_Setup`, whose README carries the same walkthrough).

**Step 4 (version control).** Publish the folder on GitHub so collaborators
can clone it:

```bash
git init
git add .
git commit -m "HospitalDataAnalysis: first patient cohort analysis"
git remote add origin https://github.com/<user>/HospitalDataAnalysis.git
git push -u origin main
```

A `.gitignore` keeps generated artifacts out of the history (`env/`,
`__pycache__/`, `*.pyc`, `.ipynb_checkpoints/`); only source, data, and
`requirements.txt` are tracked.

**Step 5 (environment sharing).** Make the toolchain reproducible for anyone
who clones the repository:

```bash
pip freeze > requirements.txt     # pin the exact installed versions
git add requirements.txt
git commit -m "Pin environment with requirements.txt"
git push
```

Anyone can then reconstruct the environment with
`pip install -r requirements.txt` inside a fresh `venv` — the same
workflow applied at repository level by the unified `requirements.txt` of
`APSD_TAI_LAB`.

## 8. Common Pitfalls & Best Practices
- **Hardcoded File Paths**: Always use relative paths (`../data/patients.csv`)
  rather than machine-specific absolute paths to ensure portability across
  different machines. (The lab notebooks go further with a portable Step-0
  bootstrap cell that locates the project folder from any working directory.)
- **Git Commits of Environments**: Never commit the `env/` virtual
  environment folder to Git. Track dependencies using `requirements.txt`
  instead.
- **Unverified Statistics**: Never write summary numbers (means, ranges,
  thresholds) from memory — always recompute them from the CSV with
  `df.describe()` before quoting them in a report.
