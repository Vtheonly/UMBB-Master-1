## 2. The Cell Geometry and the Rule Groups

A 2×2 LR cell has four known corners; the missing sub-pixels are the centre $X$ and the four edge mid-points $N, S, W, E$:

```text
v(0,0) -------- N -------- v(0,1)
  |                          |
  W            X             E
  |                          |
v(1,0) -------- S -------- v(1,1)
```

Four rule groups cover the 12 stencils (paper §3.2):

- **Group A (bilinear fallback, stencils 0–1 and untouched samples):** $N = \tfrac12(v_{0,0}+v_{0,1})$, $S = \tfrac12(v_{1,0}+v_{1,1})$, $W = \tfrac12(v_{0,0}+v_{1,0})$, $E = \tfrac12(v_{0,1}+v_{1,1})$, $X = \tfrac14(v_{0,0}+v_{0,1}+v_{1,0}+v_{1,1})$.
- **Group B (pure diagonals 2 `/` and 3 `\`):** only $X$ changes — anti-diagonal average for `/`, main-diagonal average for `\`.
- **Group C (steep 4–7):** the mid-points crossed by the contour **and** $X$ take the diagonal average (e.g. stencil 4 gentle `/`: $W = E = X = \tfrac12(v_{1,0}+v_{0,1})$).
- **Group D (mixed 8–11):** one mid-point takes the value of the *other axis* mid-point (e.g. stencil 8: $W \leftarrow N$, $E \leftarrow S$).

Assembly on the `(2h, 2w)` grid: originals at even coordinates, centres at odd/odd, shared mid-points averaged between adjacent cells, last row/column extrapolated by duplication.

## 3. Trap Deep-Dives

### 3.1 Why `(2h, 2w)` — and where `(2H−1, 2W−1)` comes from

An LR image of $h$ rows carries $h$ sample rows; doubling with the cellular placement $v_{i,j} \mapsto (2i, 2j)$ fills rows $0 \ldots 2h-2$, leaving row $2h-1$ empty — that is the `(2h−1)` grid, and it is a **complete** output for the centre-rule reduction only. The Getreuer interpolation as implemented in the lab duplicates the last computed row/column (`out[-1, :] = out[-2, :]`, `out[:, -1] = out[:, -2]`) to return exactly `(2h, 2w)` — the shape every benchmark (PSNR against the 512×512 ground truth, cascade 4× = two 2× passes) assumes. **Exam rule: the lab's `super_resolution_contour_stencils_2x` returns `(2h, 2w)`; the `(2H−1, 2W−1)` claim contradicts `TAI/utils/super_res.py` and is wrong for this course.**

### 3.2 Interpolating ALONG the edge (the core idea)

TV is small along a contour (intensity nearly constant) and large across it. Selecting the minimum-TV stencil (Eq. 6 of the paper) minimizes the Theorem 3.1 error bound $|\hat u(x) - u(x)| \le \max(|1-\lambda|, |\lambda|)\,\text{TV}(C)$ — so the interpolant is placed **along** the estimated contour. Averaging the high-TV diagonal instead would cross the edge and blur it.

### 3.3 Why 12 stencils and not 2

The two pure diagonals only resolve 45° edges. Real documents contain vertical strokes, horizontal baselines, gentle (~26.6°, arctan ½) and steep (~63.4°, arctan 2) strokes, and mixed junctions. The 12-stencil set distinguishes **8 orientations** plus 4 mixed shapes — under-selecting collapses gentle edges onto the nearest diagonal and produces staircase artifacts, exactly what the algorithm exists to avoid.

### 3.4 The Worked Centre-Example (verified reduction)

Cell $[120, 140; 100, 180]$ — reduced to the two diagonal stencils: $\text{TV}_1 = |120-180| = 60$ (main), $\text{TV}_2 = |100-140| = 40$ (anti). $\text{TV}_2 < \text{TV}_1$, so $X = \tfrac12(100+140) = 120$. **Label it explicitly as the Group-B reduction** — the full module also assigns $N, S, W, E$ by the winning stencil's group and averages shared mid-points; on this cell (stencil 2 wins) it returns the 4×4 block `[[120, 130, 140, 140], [110, 135, 160, 160], [100, 140, 180, 180], [100, 140, 180, 180]]` (verified against `TAI/utils/super_res.py` with `rho=0.0`).

### 3.5 Order of operations in the assembly

Detection (12 TV maps → `argmin`) happens **before** any interpolation; then the rule groups fill `n_val/s_val/w_val/e_val/x_val` per cell; then the assembly walks the `(2h, 2w)` grid — originals, centres, first/last rows of mid-points, **interior** mid-points as averages of adjacent cells, and only then the extrapolated rim. Writing mid-points before centres (or per-cell values instead of shared averages) double-counts or overwrites neighbours.

## 4. Motor-Recall Code Templates

The canonical module is long; the exam-safe skeleton below reproduces its structure (grayscale, `rho=0` for clarity — the lab default is `rho=0.5`). The setup lines define a tiny `lr` and a stand-in `tv_maps` so the skeleton runs standalone; on paper, write the numbered stages in order:

```python
import numpy as np

lr = np.array([[10, 20, 30, 40],
               [12, 22, 32, 42],
               [14, 24, 34, 44],
               [16, 26, 36, 46]], dtype=np.uint8)
tv_maps = np.random.RandomState(0).rand(12, 3, 3)  # stand-in detection maps

h, w = lr.shape
out = np.zeros((2 * h, 2 * w), dtype=np.float64)
img_f = lr.astype(np.float64)

# 1. originals at even coordinates
out[0:2 * h:2, 0:2 * w:2] = img_f

# 2. detection: 12 weighted TV maps (length-normalized), then argmin
best = np.argmin(tv_maps, axis=0)          # (h-1, w-1) stencil index

# 3. rule groups on the four corners tl, tr, bl, br of every cell
tl, tr = img_f[:-1, :-1], img_f[:-1, 1:]
bl, br = img_f[1:, :-1], img_f[1:, 1:]
x_val = 0.25 * (tl + tr + bl + br)          # Group A default
x_val[best == 2] = 0.5 * (bl + tr)[best == 2]   # Group B: anti-diagonal
x_val[best == 3] = 0.5 * (tl + br)[best == 3]   # Group B: main diagonal
# ... Groups C and D override the crossed mid-points ...

# 4. assembly: centres, then shared mid-points averaged, then the rim
out[1:2 * h - 1:2, 1:2 * w - 1:2] = x_val
out[:, -1] = out[:, -2]                     # edge extrapolation
out[-1, :] = out[-2, :]
result = np.clip(np.round(out), 0, 255).astype(np.uint8)
print(result.shape)
```

Factor 4 uses **pyramid magnification** — apply the 2× operator twice (re-detecting orientations on the intermediate image), never a 4×-scaled variant of the rule groups.

## 6. Answer Key (verified by execution)

**Drill 1.** $\text{TV}_1 = |90 - 150| = 60$; $\text{TV}_2 = |200 - 60| = 140$. $\text{TV}_1 < \text{TV}_2$ (main diagonal flatter), so $X = \tfrac12(90 + 150) = \mathbf{120}$.

**Drill 2.** First pass: `(256, 256)`; second pass: `(512, 512)`. The first pass's originals sit at its even coordinates — $128 \times 128 = 16384$ samples; the second pass then treats those (already interpolated) values as its own originals, so the final grid's even-even coordinates hold first-pass output, not raw LR samples.

**Drill 3.** Stencil 5 Group C sets $N = S = X = \tfrac12(v_{0,0} + v_{1,1}) = \tfrac12(30 + 180) = \mathbf{105}$ for all three. $W$ and $E$ keep the Group-A bilinear defaults: $W = \tfrac12(30+20) = 25$, $E = \tfrac12(170+180) = 175$. The diagonal average is the main-diagonal one, $\tfrac12(v_{0,0}+v_{1,1})$.

**Drill 4.** Verified: every output row is `array([0, 50, 100, 150, 200, 200], dtype=uint8)` (all four rows identical). Zero vertical differences make the vertical stencil (0) win everywhere, so the mid-points keep their bilinear defaults: originals at columns 0/2/4, centres at 50 and 150, and column 5 is the extrapolated rim (duplicate of column 4).

**Drill 5.** Line 1: wrong grid — `(2h−1, 2w−1)` instead of `(2h, 2w)` (the lab algorithm extrapolates the rim, so the buffer must have the full doubled size). Line 2: centre slice overruns — with `(2h, 2w)` the centres are `out[1:2*h-1:2, 1:2*w-1:2]` (there are only `h−1` cells per axis); `1:2*h:2` writes one row/col too far and collides with the rim. Line 3: missing `0.5 *` factor — shared mid-points are the **average** of the two adjacent cells' values, not their sum.

**Drill 6.**

```python
import numpy as np

# harness: a small image and its main-diagonal difference map
h, w = 4, 5
ch, cw = h - 1, w - 1
da = np.arange((h + 1) * (w + 1), dtype=np.float64).reshape(h + 1, w + 1)

# the answer: stencil 3's weighted, length-normalized TV at every cell
tv = (16 * da[1:1 + ch, 2:2 + cw] + 16 * da[0:0 + ch, 1:1 + cw]
      + 59 * da[1:1 + ch, 1:1 + cw] + 16 * da[2:2 + ch, 1:1 + cw]

print(tv.shape)  # (3, 4): one TV value per cell
```
