## 1. Two Extensions of the Same Grammar
Matplotlib produces a static picture: once `savefig` has written the PNG, the reader cannot see which month a bar belongs to or which patient a point is. Plotly closes that gap by writing the figure as HTML with its own JavaScript library, so the hover box, the zoom and the legend toggles travel with the file. The grammar changes only slightly: a `plotly.express` function takes the whole `DataFrame` plus column names and returns a `Figure` object, which is two containers — `fig.data` (the traces) and `fig.layout` (title, axes, legend).

Basemap belongs to the same chapter for a different reason: it adds a geographic coordinate system to an ordinary Matplotlib axes. A city is no longer drawn at an arbitrary position but at the projected position of its longitude and latitude, on top of coastlines and country borders. The chapter presents it with a deprecation note, so the goal here is conceptual — understand the four steps (create the map, draw the background, project the coordinates, plot) — and not a new dependency.

## 3. Syntax Matrix (Stage 4 — Interactive and Geographic Figures)

| I want to... | Call | Status | What you get |
| :--- | :--- | :--- | :--- |
| Draw a bar chart from a `DataFrame` | `px.bar(sales, x="Month", y="Total_Sales")` | Executed | A `Figure` whose first trace has type `bar` |
| Add columns to the hover box | `hover_data=["Max_Product"]` | Executed | The column is stored in `customdata` and appended to the hover template |
| Draw a scatter plot | `px.scatter(hospital, x="TotalCost", y="Satisfaction", hover_data=["City", "Department"])` | Executed | Trace type `scatter`, mode `markers` |
| Draw a line through ordered points | `px.line(sales, x="Month", y="Total_Sales", markers=True)` | Executed | Trace type `scatter`, mode `lines+markers` |
| Give the chart a title in the call | `title="Monthly sales"` | Executed | `fig.layout.title.text` is set |
| Rename an axis | `labels={"Total_Sales": "Units sold"}` | Executed | The axis title replaces the column name |
| Change title and axes afterwards | `fig.update_layout(title=..., xaxis_title=..., yaxis_title=...)` | Executed | Same figure, edited `fig.layout` |
| Display the figure | `fig.show()` | Executed | Opens the interactive figure (renders inline in a notebook) |
| Export for a web page | `fig.write_html("sales.html")` | Executed | One self-contained HTML file, plotly.js embedded |
| Export a small HTML file | `fig.write_html("sales.html", include_plotlyjs="cdn")` | Executed | About 8 kB instead of about 4.8 MB, but the viewer needs internet access |
| Export a static image | `fig.to_image(format="png")` | Executed | Fails here with `RuntimeError`: the `kaleido` engine needs Google Chrome |
| Pass a Matplotlib `Axes` | `px.bar(sales, x="Month", y="Total_Sales", ax=ax)` | Executed | `TypeError`: there is no `ax=` keyword |
| Build a Mercator map | `Basemap(projection="merc", llcrnrlon=..., llcrnrlat=..., urcrnrlon=..., urcrnrlat=...)` | Conceptual | A map object `m` that owns a Matplotlib axes |
| Draw the map background | `m.drawcoastlines()`, `m.drawcountries()`, `m.fillcontinents()` | Conceptual | Coastlines, borders and a filled land mask |
| Place a city by its coordinates | `x, y = m(lon, lat)` | Conceptual | Longitude/latitude in degrees converted to x/y in meters |

## 4. Exact Signatures (Plotly — Executed)

### 4.1 `px.bar` with `hover_data`
The DataFrame comes first, then the roles: `x` and `y` are column names, `title` goes to the layout, and `hover_data` is a list of the extra columns the reader should see.

```python
import plotly.express as px

fig = px.bar(
    sales,
    x="Month",
    y="Total_Sales",
    title="Monthly sales (TP4 project)",
    hover_data=["Max_Product"],
)

print(type(fig).__name__, "| trace type:", fig.data[0].type, "| traces:", len(fig.data))
print("title:", fig.layout.title.text)
print("axis titles:", fig.layout.xaxis.title.text, "/", fig.layout.yaxis.title.text)
print("first bar:", fig.data[0].x[0], fig.data[0].y[0], "| hover column:", fig.data[0].customdata[0].tolist())
fig.show()
```

Three properties of this one call are worth memorising. First, the axis titles default to the column names (`Month` and `Total_Sales`), which is why renaming a column for display is a separate step. Second, one call produces one trace, whatever the number of bars: the bars are arrays `fig.data[0].x` and `fig.data[0].y`. Third, `hover_data` does not change the drawing at all; it only enlarges the tooltip.

### 4.2 The hover template
`hover_data` stores the extra columns in `trace.customdata` and rewrites `trace.hovertemplate`. Read the template to understand what the reader will see:

```python
print(fig.data[0].hovertemplate)
```

The output is `Month=%{x}<br>Total_Sales=%{y}<br>Max_Product=%{customdata[0]}<extra></extra>`: `%{x}` and `%{y}` are the bar's own values, `%{customdata[0]}` is the first extra column, `<br>` breaks the line inside the tooltip, and the empty `<extra>` block removes the secondary box that would otherwise repeat the trace name.

### 4.3 Titles and axis labels
There are two places to fix a title. `labels=` in the call replaces every occurrence of a column name used as text (here the two axis titles), and `update_layout` edits the figure after the fact. The chapter uses both; neither raises on an unknown key — only on a misspelled keyword of `update_layout` itself.

```python
fig = px.bar(sales, x="Month", y="Total_Sales", labels={"Total_Sales": "Units sold", "Month": "Month of 2025"})
print("after labels= ->", fig.layout.xaxis.title.text, "/", fig.layout.yaxis.title.text)

fig.update_layout(title="Monthly sales", xaxis_title="Month", yaxis_title="Units sold", title_font_size=18)
print("after update_layout -> title:", fig.layout.title.text, "| font size:", fig.layout.title.font.size)
print("axis titles:", fig.layout.xaxis.title.text, "/", fig.layout.yaxis.title.text)
```

### 4.4 `px.scatter` with `hover_data`
The scatter plot is where `hover_data` matters most: eight points carry no patient identity by themselves, and the tooltip restores it.

```python
fig = px.scatter(hospital, x="TotalCost", y="Satisfaction", hover_data=["City", "Department"])
print("trace type:", fig.data[0].type, "| mode:", fig.data[0].mode, "| points:", len(fig.data[0].x))
print("first hover row:", fig.data[0].customdata[0].tolist(), "| last hover row:", fig.data[0].customdata[7].tolist())
print(fig.data[0].hovertemplate)
fig.show()
```

### 4.5 `px.line` with markers
`px.line` also returns a `scatter` trace; only the `mode` differs. Without `markers=True` the mode is `lines`, with it the mode is `lines+markers`.

```python
fig = px.line(sales, x="Month", y="Total_Sales", markers=True, hover_data=["Max_Product"])
print("trace type:", fig.data[0].type, "| mode:", fig.data[0].mode)
fig.show()

fig = px.line(sales, x="Month", y="Total_Sales")
print("without markers= -> mode:", fig.data[0].mode)
```

## 5. Trap Deep-Dives (Plotly — Executed)

### 5.1 The DataFrame is not optional when `x` and `y` are names
`x="Month"` is a column *name*. Without `data_frame`, Plotly has nothing to look the name up in and refuses immediately.

```python
def outcome(call):
    try:
        call()
        return "runs"
    except Exception as error:
        return f"{type(error).__name__}: {' '.join(str(error).split())[:95]}"

print(outcome(lambda: px.bar(x="Month", y="Total_Sales")))
```

The exception is a `ValueError` whose message says that string or integer arguments are only possible when a DataFrame or an array is provided in the `data_frame` argument. Pass the frame (`px.bar(sales, x="Month", y="Total_Sales")`) or pass real arrays (`px.bar(x=sales["Month"], y=sales["Total_Sales"])`), never bare names.

### 5.2 No `Axes` to receive
A Plotly figure is not a Matplotlib figure. Everything that targets an `Axes` — the `ax=` keyword, `set_title`, `savefig`, `set_xlabel` — raises an `AttributeError` or a `TypeError`.

```python
print(outcome(lambda: px.bar(sales, x="Month", y="Total_Sales", ax=None)))
print(outcome(lambda: fig.set_title("Monthly sales")))
print(outcome(lambda: fig.savefig("sales.png")))
```

The right verbs are `title=` or `fig.update_layout(title=...)`, and `fig.write_html(...)` for the file.

### 5.3 `hover_data` is one word with an underscore
Both the misspelled keyword and the misspelled column fail, with two different exceptions.

```python
print(outcome(lambda: px.bar(sales, x="Month", y="Total_Sales", hoverdata=["Max_Product"])))
print(outcome(lambda: px.bar(sales, x="Month", y="Total_Sales", hover_data=["Max_Produt"])))
print(outcome(lambda: px.line(sales, x="Month", y="Total_Sales", marker="o")))
```

`hoverdata=` is a `TypeError` (unknown keyword), a column typo in `hover_data` is a `ValueError` that lists the valid column names, and `px.line(marker="o")` is a `TypeError`: the keyword of `px.line` is the plural `markers`, a boolean, not the Matplotlib format string.

### 5.4 A misspelled `update_layout` keyword
```python
print(outcome(lambda: fig.update_layout(titel="Monthly sales")))
print(outcome(lambda: __import__("ploty.express")))
```

`update_layout` validates its keywords against the list of layout properties, so `titel=` raises a `ValueError` that even suggests the right spelling. The module itself is `plotly` (with a `y`); `ploty` is a `ModuleNotFoundError`.

### 5.5 Omitting `y` counts rows instead of summing them
`px.bar(sales, x="Month")` runs without error. It draws the number of rows per category, which is 1 for every month here.

```python
fig = px.bar(sales, x="Month")
print("no y= -> bar heights:", sorted(set(fig.data[0].y.tolist())), "| y axis title:", fig.layout.yaxis.title.text)
```

The y axis title becomes `count`. A flat chart of ones after "forgetting" `y=` is this trap, not a data problem.

### 5.6 Text categories keep the order of appearance
Month names are strings, so Plotly treats them as a category in the order it first meets them. It does not sort them alphabetically and it does not sort them chronologically either: a shuffled frame gives a shuffled line.

```python
shuffled = sales.sample(frac=1, random_state=1)
print("months as drawn from a shuffled frame:", list(px.line(shuffled, x="Month", y="Total_Sales").data[0].x)[:4], "...")

horizontal = px.bar(sales, x="Total_Sales", y="Month")
print("x and y swapped -> orientation:", horizontal.data[0].orientation)
```

Sort the frame (or use a real date column) before drawing a line. The last two lines show a useful corollary of the same grammar: swapping `x` and `y` turns the bars horizontal (`orientation` becomes `h`).

### 5.7 Two export engines, one of them external
`write_html` is pure Python and always works. `to_image` and `write_image` delegate to the `kaleido` package, which in turn needs a Chrome installation.

```python
import os
import tempfile

fig = px.bar(sales, x="Month", y="Total_Sales", hover_data=["Max_Product"])
folder = tempfile.mkdtemp()

full = os.path.join(folder, "sales_full.html")
cdn = os.path.join(folder, "sales_cdn.html")
fig.write_html(full)
fig.write_html(cdn, include_plotlyjs="cdn")
print("self-contained HTML:", os.path.getsize(full), "bytes")
print("CDN HTML:", os.path.getsize(cdn), "bytes")
print("JSON:", len(fig.to_json()), "bytes")

import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

fig_mpl, ax = plt.subplots(figsize=(6, 4))
ax.plot(sales["Month"], sales["Total_Sales"], marker="o", color="tab:blue")
ax.set_title("Monthly sales")
ax.set_ylabel("Total_Sales")
for extension in ("png", "svg", "pdf"):
    path = os.path.join(folder, f"sales.{extension}")
    fig_mpl.savefig(path, dpi=100)
    print(f"Matplotlib {extension}:", os.path.getsize(path), "bytes")
plt.close(fig_mpl)

print("to_image ->", outcome(lambda: fig.to_image(format="png")))
```

## 6. Plotly versus Matplotlib — Measured Trade-Offs
The block above draws the same monthly series with both libraries and prints the file sizes. Three numbers sum up the choice.

| Criterion | Plotly (`plotly.express`) | Matplotlib |
| :--- | :--- | :--- |
| Output | HTML with embedded JavaScript | PNG, SVG, PDF |
| Hover box | Built in, extended by `hover_data` | None; a value must be written on the chart with `text` or `annotate` |
| Zoom, pan, legend toggle | Built in, also inside the exported HTML | Only in the notebook toolbar, never in the exported image |
| Size of the file | 4,847,253 bytes self-contained, 8,442 bytes with `include_plotlyjs="cdn"` | 31,194 bytes (PNG), 28,735 bytes (SVG), 14,009 bytes (PDF) for the same series |
| Static image | Needs `kaleido` and Chrome; raises `RuntimeError` in this environment | `savefig` only |
| Object model | `Figure` holding `data` and `layout` | `Figure` holding `Axes` |
| Target an existing axes | Not possible (`ax=` is a `TypeError`) | The normal way of composing panels |
| Default axis titles | The column names | None until `set_xlabel` / `set_ylabel` |
| Title | `title=` or `fig.update_layout(title=...)` | `ax.set_title(...)` |

The decision rule for the course material follows from the table. Use Matplotlib for a printed report, a PDF deliverable, and any `subplots` layout with shared axes; use Plotly when the reader will open the file on a screen and needs to interrogate points — a dashboard, an exploratory HTML page, or the monthly sales series where the best product of each month should appear on hover. The CDN file is the right choice for a web page; the self-contained file is the right choice for an e-mail attachment read offline.

## 7. Basemap — Conceptual (Not Executed Here)
The chapter spends pages 20–23 on `mpl_toolkits.basemap.Basemap` and adds a deprecation note on page 20. Nothing below was executed: `import mpl_toolkits.basemap` raises `ModuleNotFoundError` in this environment, and the repository does not install it. The signatures are quoted from the official API reference (`matplotlib.org/basemap/stable/api/basemap_api.html`, release 2.0.0).

### 7.1 What the package is, and its status
The constructor signature of the reference is `Basemap(llcrnrlon=None, llcrnrlat=None, urcrnrlon=None, urcrnrlat=None, ..., width=None, height=None, projection='cyl', resolution='c', ..., lat_ts=None, lat_0=None, lon_0=None, ..., ax=None)`. Only five arguments matter for the chapter: the projection, the two corners of the map, and the resolution of the coastline database.

The chapter's deprecation note names Cartopy as the successor for new code. What upstream shows today (checked 2026-11-26) is more nuanced: the GitHub README (`github.com/matplotlib/basemap`) carries no deprecation sentence, PyPI lists `basemap` 2.0.0 with the summary "Plot data on map projections with matplotlib" and dependencies limited to numpy, matplotlib, pyproj, pyshp and basemap-data, and the documentation is hosted by matplotlib.org (release 2.0.0, dated Jun 13, 2025). The package still installs and is still documented, but it is a legacy toolkit built on its own bundled data. The course decision is therefore to **learn the concepts, add no dependency**, and start new geographic work with Cartopy.

### 7.2 The four steps
1. **Create the map.** `projection="merc"` selects the Mercator cylindrical projection. `llcrnrlon`, `llcrnrlat`, `urcrnrlon`, `urcrnrlat` are the longitude and latitude (in degrees) of the lower-left and upper-right corners. `lat_ts` is the latitude of true scale; the reference states that it is optional for the Mercator projection and defaults to 0. `resolution` is one of `c` (crude), `l` (low), `i` (intermediate), `h` (high), `f` (full) or `None`, with `c` as the default and higher resolutions much slower to draw.
2. **Draw the background.** The reference gives `drawcoastlines(linewidth=1.0, linestyle='solid', color='k', ...)`, `drawcountries(linewidth=0.5, linestyle='solid', color='k', ...)` and `fillcontinents(color='0.8', lake_color=None, ..., alpha=None)`.
3. **Project the coordinates.** "Calling a Basemap class instance with the arguments lon, lat will convert lon/lat (in degrees) to x/y map projection coordinates (in meters)." The inputs may be scalar floats, sequences or arrays, and the keyword `inverse=True` performs the reverse conversion.
4. **Plot** with ordinary Matplotlib calls on the axes the map object created (`m.ax`).

```
from mpl_toolkits.basemap import Basemap
import matplotlib.pyplot as plt

fig = plt.figure(figsize=(7, 6))
m = Basemap(
    projection="merc",
    llcrnrlon=-9.0, llcrnrlat=18.0,
    urcrnrlon=12.0, urcrnrlat=38.0,
    resolution="l",
)
m.drawcoastlines(linewidth=0.8)
m.drawcountries(linewidth=1.0)
m.fillcontinents(color="0.9", lake_color="white")
m.drawmapboundary(color="black")

cities = {"Algiers": (3.09, 36.73), "Oran": (-0.64, 35.70), "Annaba": (7.77, 36.90)}
for name, (lon, lat) in cities.items():
    x, y = m(lon, lat)
    plt.plot(x, y, "ro", markersize=6)
    plt.text(x, y, " " + name, fontsize=9, va="center")

plt.title("Hospital cities (Mercator projection)")
plt.show()
```

The corner values are an approximate frame chosen to cover the north of the country where the three hospital cities lie; they are a choice, not a rule. The city coordinates were looked up with the Open-Meteo geocoding service (Algiers 36.73 N, 3.09 E; Oran 35.70 N, 0.64 W; Annaba 36.90 N, 7.77 E) and rounded to two decimals.

### 7.3 The concepts an exam can target
- **Projection.** A projection maps the curved surface of the Earth onto a plane. `merc` preserves angles and shapes locally but inflates areas away from the equator; the default `cyl` is the simpler equidistant cylinder. For the cylindrical projections (`cyl`, `merc` and others) the reference notes that the default corners are llcrnrlon=-180, llcrnrlat=-90, urcrnrlon=180, urcrnrlat=90, i.e. the whole world unless corners are given.
- **Geographic versus projected coordinates.** Longitude/latitude in degrees are *data*; x/y in meters are *positions on the canvas*. `m(lon, lat)` is the only place where the conversion happens, so a point drawn with the raw longitude and latitude would land at the wrong place.
- **Resolution versus speed.** `resolution="f"` reads the full GSHHS coastline database and is much slower; `resolution=None` reads no boundary data at all, and the reference warns that the drawing methods then fail when invoked.
- **Layering.** The background is drawn first, the data last, exactly as `imshow` precedes `scatter` on an image axes.
