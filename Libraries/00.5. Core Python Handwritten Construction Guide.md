Every drill answer below was executed in Python (3.12) before being written down.

## 1. Handwritten Syntax Rules (the mechanical marks)

| Rule | On paper this means | Typical deduction |
| :--- | :--- | :--- |
| Indentation | **4 spaces per block level**, one level per `:` block. Never mix tabs visually — rule a straight left edge. | An `if` body written at the same column as the `if` reads as *not part of the branch* — logic error, full marks lost. |
| Colons | Every compound header ends with `:` — `if c:`, `for x in s:`, `def f():`, `class C:`, `try:`. | `SyntaxError` — one mark per missing colon. |
| Matched brackets | Every `(`, `[`, `{` closes. Count pairs before moving on; end-of-line `(` continues the expression. | `SyntaxError: '(' was never closed`. |
| `=` vs `==` | `=` **assigns** (statements), `==` **compares** (conditions). | `if x = 0:` is a syntax error on paper — graders spot it instantly. |
| **No semicolon one-liners** | One statement per line. `a = 1; b = 2` is forbidden in handwritten answers — write two lines. | Readability deduction + missed indentation marks. |
| Quotes | `'single'` or `"double"` are equivalent — pick one and stay consistent within a line. | Wasted time re-writing. |
| `def` returns | A bare `return` gives `None`; `return a, b` builds a **tuple**. | "Missing return" is the most common zero-mark bug. |

## 2. The Problem-to-Python Construction Method

Use this fixed six-step method for every "write a program/function that…" question. It mirrors how the TP3 pipeline ([[02.11. Tutorial 03 - Modular Sales Inventory Processing Pipeline]]) decomposes into `clean_lines` → `parse_products` → `Product` → analysis:

1. **Parse inputs/outputs** — write at the top of the page: *given* (types: list? str? file? int?) → *wanted* (one value? a list? printed lines?). Name the variables NOW (`values`, `total`, `out`).
2. **Choose the structure** — map the problem shape to a construct: "transform every element" → comprehension or `map`; "keep some elements" → `filter`/`if` inside a comprehension; "reduce to one number" → accumulator loop; "two sequences in step" → `zip`; "state + behaviour" → class; "huge data, one row at a time" → generator (`yield`); "may fail" → `try`/`except`.
3. **Initialize** — declare the accumulator *before* the loop: `total = 0`, `out = []`, `counts = {}`, `buffer = np.zeros((h, w), dtype=np.uint8)`. An uninitialized accumulator is the #1 paper bug.
4. **Pseudocode** — 3–5 lines of plain language, one per loop body action, *in order*.
5. **Write** — translate each pseudocode line to exactly one Python line, indenting one level inside each block.
6. **Hand-trace edge cases** — run the code in the margin with a tiny input: the empty list, a single element, and the boundary value of every condition (`>` vs `>=` — e.g. `seuillage_fixe_perso` uses **strictly greater than** the threshold).

## 3. Syntax Matrix - What Breaks vs. What Runs

| You are writing... | Correct form | Fatal handwritten form | Failure mode |
| :--- | :--- | :--- | :--- |
| Default dict counter | `counts[k] = counts.get(k, 0) + 1` | `counts[k] += 1` on a missing key | `KeyError` — `.get(k, 0)` supplies the default. |
| Add to a list | `rows.append(x)` | `rows += [x]` used by habit | Works, but `append` is the exam idiom; `rows.append(x, y)` (two args) is a `TypeError`. |
| f-string | `f"{last.capitalize()}, {qty:.2f}"` | `"{last}, {qty}"` | Missing `f` prefix → literal braces printed. |
| Generator function | `def g():` … `yield x` | `return x` inside, or `yield` outside a function | `yield` anywhere in a `def` makes it a generator; calling it returns the generator object, **not** a value. |
| Consume a generator | `next(gen)` / `sum(gen)` | `gen[0]` | Generators are single-pass and not subscriptable. |
| Class attribute | `Patient.count += 1` | `count += 1` inside a method | Assignment makes `count` a **local** variable → `UnboundLocalError`. Class attrs must be qualified (`ClassName.attr` or read via `self`). |
| Instance attribute | `self.name = name` in `__init__` | `name = name` | The parameter dies with the call; the object never stores it. |
| `__add__` | `def __add__(self, other):` `return self.price + other.price` | `return self.price + other` | Then `p1 + p2` crashes — `int + Product` has no `__add__` that returns NotImplemented usefully. |
| File write | `with open("out.txt", "w") as f:` | mode `"r"` then `f.write(...)` | `io.UnsupportedOperation: not writable`. |
| Append without clobbering | `open(path, "a")` | `open(path, "w")` on an existing file | `"w"` **truncates** the file to zero length immediately. |
| Except clause | `except (ValueError, TypeError):` | `except ValueError, TypeError:` | Old Python 2 syntax — `SyntaxError` in Python 3. |
| Integer input | `int("41")` → `41` | `int("4.5")` | `ValueError` — go through `float` first. |

## 4. Construction Templates (Chapter 3 Parts 1–2 canon)

### 4.1 Accumulator loop with a condition (the base pattern)

```python
def accumulate(values):
    total = 0
    counts = {}
    for v in values:
        total += v
        key = v % 2
        counts[key] = counts.get(key, 0) + 1
        if total > 12:
            break
    return total, counts
```

### 4.5 Class: `__init__`, `self`, class vs instance attributes, `__add__`

```python
class Product:
    count = 0                                  # CLASS attribute (shared counter)

    def __init__(self, name, price, quantity):
        self.name = name                       # INSTANCE attributes (per object)
        self.price = price
        self.quantity = quantity
        Product.count += 1                     # qualify the class attribute!

    def total_value(self):
        return self.price * self.quantity

    def __add__(self, other):
        return self.price + other.price        # p1 + p2 -> combined price

    def __str__(self):
        return f"Product({self.name}, Price={self.price:.2f}, Qty={self.quantity})"
```

This is exactly the TP3 `Product` of `APDS/02_Sales_Inventory_Pipeline/utils/product.py` (plus the exam counter and `__add__`).

### 4.6 Generator: `yield` (the 1M-record memory pattern)

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

gen = countdown(3)      # nothing runs yet - gen is a paused generator
next(gen)               # 3  (execution pauses AT the yield)
sum(gen)                # 3  (2 + 1: the generator resumes and finishes)
```

Generators carry one row at a time — the design that lets [[02.7. The 1 Million Records Memory Explosion Autopsy and Production Streaming Solutions]] stream 1,000,000 patients instead of loading them.

### 4.7 `try` / `except` / `else` / `finally` (full clause order)

```python
def parse_age(raw):
    try:
        age = int(raw)                 # the risky line ONLY
    except ValueError:
        result = None                  # the recovery
    else:
        result = age + 1               # runs only if try succeeded
    finally:
        print("parsed:", raw)          # ALWAYS runs, even around return
    return result
```

Clause order is fixed: `try` → `except` (0..n) → `else` → `finally`. Put **one risky line** in `try`; a whole program inside `try` hides real bugs.

## 7. Self-Audit Checklist

- [ ] Every compound header ends with a colon; each block indents one more level (4 spaces).
- [ ] Accumulators initialized **before** the loop; `return` present (a bare loop end returns `None`).
- [ ] `==` in every condition; `=` only on its own assignment line; no semicolons packing statements.
- [ ] `lambda` used only as an expression (`key=lambda p: p.price`), never with statements.
- [ ] Class attributes qualified (`Product.count`); instance attributes assigned through `self` in `__init__`.
- [ ] Files opened with `with open(...) as f:`; write mode `"w"`, append `"a"`, read `"r"` — never mixed.
- [ ] `try` holds only the risky line; clauses in order `except` → `else` → `finally`; tuple exceptions `except (ValueError, TypeError):`.
- [ ] Boundary traced: `>` vs `>=` checked against the reference (e.g. `seuillage_fixe_perso` is strict).
