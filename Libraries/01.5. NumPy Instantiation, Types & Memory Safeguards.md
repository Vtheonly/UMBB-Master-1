## 1. Syntax Matrix - What Breaks vs. What Runs

| You are writing... | Correct form | Fatal handwritten form | Failure mode |
| :--- | :--- | :--- | :--- |
| A 2D zero buffer | `np.zeros((10, 10))` | `np.zeros(10, 10)` | `TypeError` — the second loose argument is parsed as a `dtype`, not a second dimension. Shape arguments for `zeros`/`ones`/`full`/`empty` travel **inside one tuple**. |
| An array from values | `np.array([1, 2, 3])` | `np.array(1, 2, 3)` | `TypeError` — `np.array` takes ONE positional object; wrap the values in a list (or nested lists for 2D). |
| Constant fill | `np.full((2, 3), 7)` | `np.full(2, 3, 7)` | `TypeError` — the shape must be the first **tuple**; the fill value is the second positional. |
| Identity matrix | `np.eye(3)` / `np.identity(3)` | `np.eye(3, 3)` expecting a tuple rule | Works (`np.eye(N, M)` makes a rectangular diagonal), but the exam form is `np.eye(N)`; `np.identity(n)` accepts only one integer. |
| Uninitialized buffer | `np.empty((h, w))` | assuming zeros | `empty` returns **arbitrary memory garbage** — only the shape/dtype are guaranteed. Zero it yourself if zeros are required. |
| Index-built grid | `np.fromfunction(lambda i, j: i + j, (2, 3))` | `np.fromfunction(i, j: i + j)` | `SyntaxError` (lambda needs its own keyword); the shape is a **tuple**, and the function receives **coordinate arrays**, not scalars, so it must use array-safe operations. |
| Iterable → array | `np.fromiter((x*x for x in r), dtype=np.float64, count=4)` | `np.array(generator)` | `np.array` on a generator yields a **0-d object array**; `fromiter` is the constructor that consumes iterators (and `dtype` is **mandatory**). |
| Shape probe | `img.shape` | `img.shape()` | `TypeError` — `shape`, `dtype`, `ndim`, `size`, `nbytes`, `strides` are attributes (struct fields), never methods. |
| Type probe | `img.dtype` | `img.dtype()` | Same attribute rule. |
| Sequence, stop exclusive | `np.arange(0, 10, 2)` | expecting `10` inside | `arange` **excludes** the stop: gives `[0, 2, 4, 6, 8]`. |
| Sequence, stop inclusive | `np.linspace(0, 1, 5)` | expecting `1` excluded | `linspace` **includes** both endpoints: `[0.0, 0.25, 0.5, 0.75, 1.0]`. |
| Float cast | `img.astype(np.float64)` | `img.astype(np.float64)` alone on a line | `.astype` **returns a new array**; without assignment the cast evaporates. The original `uint8` buffer is untouched. |
| Buffer clone | `arr.copy()` | `np.copy` without parentheses | `copy` is a method: call it, assign the result. |

## 2. Exact Signatures and Positional Defaults

**Running image.** Every block below assumes this cell has been run (the lab image idiom of the TAI track — see [[09.1. TP1 - Digital Image Acquisition, Matrix Topologies, and Fixed Thresholding]]):

```python
import numpy as np

img = np.array([[10, 90, 200], [45, 255, 0]], dtype=np.uint8)
h, w = img.shape
```

```python
np.zeros((3, 2))                                        # zeros(shape, dtype=float) - TUPLE
np.ones((3, 2))                                         # ones(shape, dtype=float)
np.full((2, 2), 7)                                      # full(shape, fill_value)
np.empty((2, 2))                                        # uninitialized - NOT zero
np.eye(3)                                               # eye(N) - identity; identity(N) twin
np.fromfunction(lambda i, j: i + j, (2, 3))             # f(i, j) over the grid
np.fromiter((x for x in range(4)), dtype=np.float64, count=4)   # dtype MANDATORY
np.arange(0, 10, 2)                                     # stop EXCLUSIVE
np.linspace(0, 1, 5)                                    # stop INCLUSIVE (num=50 default)
np.array([1, 2, 3])                                     # object = list / nested / tuple
```

**The tuple/scalar split, memorized:** constructors that take a *shape* (`zeros`, `ones`, `full`, `empty`, `eye`) want a shape **tuple**. Constructors that take *contents* (`array`, `fromiter`, `fromfunction`'s second argument is still a shape) want a **sequence of values**. `np.random.rand(H, W)` is the exception on the NumPy side: loose integers (see [[04.5. NumPy Math Engine, Broadcasting Rules & Axis Reductions]]).

## 3. Trap Deep-Dives

### 3.1 The Allocation Tuple Trap
`np.zeros(10, 10)` does not create a 10x10 matrix. Python hands the second `10` to the `dtype` slot, so NumPy raises `TypeError: Cannot interpret '10' as a data type`. One missing pair of parentheses is a full point deduction on paper. When the shape comes from an image, never rebuild the tuple by hand:

```python
buffer = np.zeros_like(img)                        # copies shape AND dtype in one call
buffer = np.zeros(img.shape, dtype=img.dtype)     # the explicit equivalent
```

`np.zeros_like` is the exam-safe archetype: "Pre-allocate a zero buffer matching an image's dimensions and type without hardcoding numbers."

### 3.2 Attribute vs. Method (the Parentheses Trap)
Attributes are *state*; methods are *actions*. Writing `img.shape()` adds a call to something that is not callable — instant `TypeError`. The full attribute list worth memorizing: `shape`, `dtype`, `ndim`, `size`, `itemsize`, `nbytes`, `strides`, `T` (see [[05.5. NumPy Linear Algebra, Matrix Products & Solvers]] for `.T`).

### 3.3 astype Returns a New Buffer
`.astype(np.float64)` **never mutates in place**. This is the opening move of the Float-to-Int Defensive Sandwich of [[19.5. Spatial Restoration, Integral Fast Filtering & Noise Generators]]:

```python
work = img.astype(np.float64)      # 1. capture the returned float buffer
processed = work - 50.0            # 2. compute on it
out = np.clip(np.round(processed), 0, 255).astype(np.uint8)   # 3. cast back, assigned
```

The same rule explains a silent hazard at the OpenCV boundary: `cv2.imwrite` on a `float64` buffer does **not** fail — it warns (`Unsupported depth ... fallbacked to CV_8U`, verified) and converts behind your back. The discipline is the explicit `np.clip(np.round(...), 0, 255).astype(np.uint8)` before any write.

### 3.4 arange vs. linspace Boundaries
`np.arange(0, 256, 1)` yields 0..255 (256 values, stop dropped). `np.linspace(0, 255, 256)` also yields 0..255 (endpoints kept). They agree only because the arithmetic lines up; the *convention* differs. On paper, annotate which one you chose — graders check boundary logic. The classic off-by-one: `np.arange(0, 255)` has **255** values, not 256.

### 3.5 The Constructor Zoo (executed outputs)
The six non-trivial constructors, one glance each (all outputs re-verified):

```python
import numpy as np

np.full((2, 3), 7)          # [[7, 7, 7], [7, 7, 7]]      constant fill, tuple shape
np.eye(3)                   # 3x3 identity (float64)
np.identity(3)              # identical to np.eye(3) - verified np.array_equal
np.empty((2, 2))            # shape (2, 2), dtype float64, VALUES ARE GARBAGE
np.fromfunction(lambda i, j: i + j, (2, 3))
# [[0., 1., 2.],
#  [1., 2., 3.]]            # i and j are whole coordinate ARRAYS
np.fromiter((x * x for x in range(4)), dtype=np.float64, count=4)
# [0., 1., 4., 9.]          # dtype mandatory; np.array(generator) would NOT do this
```

Two paper rules from the zoo: (1) `fromfunction`'s callback must be written **vectorized-safe** (`i + j`, `i * j`, `np.where(...)`) because it receives the whole index grid; (2) `fromiter` is the only array constructor that consumes a generator element by element — exactly the bridge from the streaming world of [[02.6. Generators, Lazy Evaluation, and Asynchronous Streaming Pipelines]].

### 3.6 empty is a contract, not a value
`np.empty((h, w))` promises only *shape and dtype*. Reusing it as "a zero image" is undefined behaviour that happens to look correct on freshly allocated memory and then corrupts results later. On paper: `empty` for "I will overwrite every element" (e.g. a pre-allocated output buffer), `zeros` for "the untouched parts must read as 0".

## 7. Answer Key (verified by execution)

**Drill 1.** `np.full((2, 3), 7)` → shape `(2, 3)`, all `7`. `np.eye(3)` → 3x3 identity (float64, diagonal 1.0). `np.empty((2, 2))` → shape `(2, 2)`, dtype `float64`, **values uninitialized** (only shape/dtype guaranteed). `np.fromfunction(lambda i, j: i + j, (2, 3))` → `[[0., 1., 2.], [1., 2., 3.]]`. `np.fromiter(...)` → `[0., 1., 4., 9.]`.

**Drill 2.** A: shape not a tuple — `TypeError: Cannot interpret '640' as a data type` (fix: `np.zeros((480, 640))`). B: the buffer is `float64` — `cv2.imwrite` does not raise but **silently falls back to a CV_8U conversion with a warning** (verified: returns `True`); the discipline is `np.clip(np.round(x), 0, 255).astype(np.uint8)` before writing. C: `arange` excludes the stop → only **255** values (0..254); all 256 levels need stop `256` (or `np.arange(256)`).

**Drill 3.**

```python
import numpy as np

a = np.linspace(0, 10, 5)
b = np.arange(0, 10, 2.5)
print(a.tolist())    # [0.0, 2.5, 5.0, 7.5, 10.0]  - stop INCLUDED, 5 values
print(b.tolist())    # [0.0, 2.5, 5.0, 7.5]        - stop EXCLUDED, 4 values
```

**Drill 4.** (a) `np.zeros((480, 640), dtype=np.uint8)`; (b) `np.zeros_like(frame)`.

**Drill 5.**

```python
import numpy as np

ramp = np.fromfunction(lambda i, j: j, (3, 8)).astype(np.uint8)
print(ramp[0].tolist())    # [0, 1, 2, 3, 4, 5, 6, 7]
```

The callback ignores `i` (row) and keeps `j` (column); `fromfunction` broadcasts it over the whole grid — verified output row: `[0, 1, 2, 3, 4, 5, 6, 7]` on all three rows.

**Drill 6.** (a) `np.float32` — verified bit-identical to `cv2.calcHist([img], [0], None, [256], [0, 256]).ravel()`. (b) NumPy integers **wrap around, they do not saturate**: once a bin holds 255, the next `+= 1` drops it back to 0 (verified: `np.uint8(255) + 1 -> 0`, with an `overflow encountered` warning). A bin hit by 256 pixels reads 0, one hit by 257 reads 1 — the counts are silently wrong long before any exception appears. `float32` counts have no such ceiling.

## 8. Self-Audit Checklist

- [ ] Every `zeros` / `ones` / `full` / `empty` shape argument is wrapped in `( )` as a single tuple.
- [ ] No `.shape()`, `.dtype()`, `.ndim()`, `.size()` anywhere — attributes are bare.
- [ ] Every `.astype(...)` result is assigned to a variable.
- [ ] `arange` stops are exclusive; `linspace` stops are inclusive — boundary noted in a comment.
- [ ] Buffers derived from images use `zeros_like` or `img.shape`, not hand-copied numbers.
- [ ] `empty` used only when every element will be overwritten; `full(shape, value)` for constant canvases.
- [ ] `fromfunction` callbacks are array-safe; `fromiter` carries `dtype=` (and `count=` when known).
- [ ] Histogram buffers are `float32`; anything fed to `cv2.imwrite` is explicitly `uint8`.
